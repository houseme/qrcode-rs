# v2.1.0 实施方案 — 安全加固 & 供应链安全(总览)

> 目标: 强化安全审计能力,建立可信赖的软件供应链。**次版本(向后兼容)。**
> 规格: `docs/roadmap/v2.1.0-security-supply-chain.md`。`docs/*` gitignore,本地记录。

## 背景

v2.0.0 workspace 落地后,安全投入:输入验证、模糊/属性测试、供应链自动化(deny/vet/SBOM/签名)、
运行时资源限制与确定性、安全文档。建立 CI 安全门禁与发布签名流程。**工期 2-3 周。**

## 范围(4 子任务)

| # | 子任务 | 文件 | 主题 |
|---|--------|------|------|
| 1 | 输入验证与运行时加固 | `v2.1.0/01-input-hardening.md` | unsafe 审计、溢出/边界、资源限制、确定性 |

## 关键设计

- **验证前置**: 非法 version/ec/mode 在入口返回 `QrError`,不进入编码内部。
- **`miri` + ASAN + fuzz** 三重内存安全门禁;`unsafe` 须有安全证明(v2.0 SIMD intrinsics 是重点审计对象)。
- **供应链**: CI 跑 `cargo deny`+`cargo vet`;Release 附 CycloneDX SBOM + Sigstore/GitHub Attestation 签名。
- **确定性**: 消除全局状态,掩码选择确定性;`deterministic` feature 强制。

## 实施顺序

1(验证/资源/确定性)→ 2(fuzz/property,依赖 1 的加固)→ 3(供应链,CI 流水线)→ 4(文档,收尾)。

## 验证(总)

- `cargo miri test --workspace` 全绿,无 UB。
- fuzz ≥ 72h 无崩溃/ASAN 违例;OSS-Fuzz 集成。
- `cargo deny check` 全绿;SBOM + 签名附 Release。
- 资源限制:超限输入明确报错、低开销;确定性:同输入跨平台同输出。

## 推迟

- 形式化验证(kani/Prusti)— 研究性质,v3.x 再评估。
- 第三方安全审计(外部机构)— 视发布节奏。
